# Security

Please don't report security problems in a public issue. Use GitHub's private reporting instead: on this repository, open the **Security** tab and choose **Report a vulnerability**. You'll get a reply there.

How Cool Head works, so you can judge what is a problem:

- **What it reads.** It runs as your user and reads what macOS lets your user read: details of your own processes (command line, folder, the files they write, the last lines of their logs) and, for other users' processes such as macOS's own, only their name and CPU use.
  - It also reads how much of the graphics chip each process uses, from the IORegistry (the same place `ioreg` reads), which needs no permission.
  - For the whole Mac, it reads macOS's memory pressure level, swap size, and the running count of memory moved to the swap files (the counts `vm_stat` shows), and the free space on the startup disk; none needs permission.
  - While the panel is open, every 3 seconds, how busy the chip is (macOS's processor counters, which `top` also reads) and the share of memory macOS counts as free when it judges memory pressure (`kern.memorystatus_level`); nothing while the panel is closed.
  - Power and sleep, from `pmset`, which any user can run: Low Power Mode for each power source (`pmset -g custom`) and which programs are holding the Mac awake, by name and process number (`pmset -g assertions`), every 5 minutes; and the sleep log (`pmset -g log`, about a week) once at launch and after each wake, for the last sleep's wakes and battery charge. The name a program gives its request to stay awake isn't kept, since it can hold a page or file title.
  - Browsers, every 10 minutes and when the panel opens (at most once a minute): for Chrome, Edge, and Brave, whether each of a fixed list of policy names that adware sets is present in the browser's settings (read with CFPreferences, as `defaults read` does; the values aren't kept, and Cool Head's own memory settings are never counted); whether this Mac is enrolled in device management (`profiles status -type enrollment`, which any user can run) or has managed settings for your account; and, for a running browser, its arguments and the name of the program that started it, to notice one started with `--load-extension`.
  - Chrome's Local State file (`~/Library/Application Support/Google/Chrome/Local State`), when memory is tight and Chrome is using the most, and again only after Chrome changes the file: only whether Chrome's setting to show each tab's memory on hover is on (`browser.hovercard.memory_usage_enabled`), so the memory card stops offering to turn it on once it is. The rest of the file, which includes Chrome's profile names, is passed over and never kept.
  - Apps that keep crashing, from macOS's crash reports in `~/Library/Logs/DiagnosticReports` (your own, always readable) and `/Library/Logs/DiagnosticReports` (macOS's, readable only on an administrator's account): at launch, every 10 minutes, after each wake, and when the panel opens (at most once a minute). Only reports from the last 24 hours are opened, and only their first line is read: the app's name, its bundle ID, the time, and the kind of report. The crash details below it are never read.
  - Hardware checks, read the same way with no password: the internal drive's own health record (wear, spare space, errors), through Apple's public plug-in for it.
  - The battery's condition, charge cycles, temperature, and charger, from the IORegistry, and its condition and Maximum Capacity from System Information (`system_profiler SPPowerDataType`), at most once an hour; for the Battery page, whether Low Power Mode is on (`ProcessInfo.isLowPowerModeEnabled`).
  - Error counters on each USB-C and MagSafe port, from the IORegistry.
  - Whether Time Machine has a backup drive set up, from `tmutil destinationinfo`, at most every 10 minutes. Not when it last backed up: that needs an administrator, or connecting the backup drive.
  - The background helpers other apps install, from their plists in `~/Library/LaunchAgents` and `/Library/LaunchAgents` (read as files, again only when one of those folders changes), to tell whether a busy process is one; and, once you've turned one off, `launchctl print-disabled` for your login session, at most once a minute, to keep its line at the top of the panel current.
  - Every 5 minutes, for each open app: its memory (with its helpers) and how many windows it has, from macOS's window list by owner (no window names or contents, and no permission needed), kept in memory for 6 hours to tell a leak from work; never written to disk.
  - When memory is tight and Ollama is among the three biggest users: which models Ollama has loaded, by asking Ollama itself on this Mac (`http://127.0.0.1:11434/api/ps`), at most every 30 seconds. Nothing leaves the Mac. When the startup disk is nearly full: how much space Xcode's build data takes (`~/Library/Developer/Xcode/DerivedData`), at most every 10 minutes.
  - For a busy app (never macOS's own programs): whether it is running translated through Rosetta (the kernel's flag for the process, which needs no permission) and which processor types its program file is built for (the file's first few bytes). On macOS 26.0 and 26.1 only, when WindowServer is busy: the Electron version inside each app you have open, from the framework's own details file.
  - For a busy program in macOS's own folders: the priority each of its threads runs at, from `ps -M` (which can read other users' processes where Cool Head's own calls can't), at most every 30 seconds; and the date and version of the last macOS update, from `/Library/Receipts/InstallHistory.plist`, which every user can read, at most once an hour.
  - While memory is tight and Chrome is among the biggest users: each Chrome process's scheduling priority, its type from its launch arguments (tab, extension, graphics, or Chrome's own program), its memory, and when Chrome's own program started, to say how much of Chrome's memory is in tabs you aren't looking at (Chrome puts those in macOS's background band) and whether a restart would help. Kept in memory only, never which tab or site.
  - Whether a busy program that calls itself by one of macOS's names, or was started by a launch item labelled `com.apple.…` in `~/Library/LaunchAgents`, `/Library/LaunchAgents`, or `/Library/LaunchDaemons`, is really Apple's: the code signature of that one program, checked against `anchor apple` (as `codesign -R="anchor apple"` does); only plists whose name starts `com.apple.` are read, as files, and only when one of those folders changes. It runs `csrutil status` and `csrutil authenticated-root status` once at start, which need no password, because with those protections off macOS's own folders can be changed.
  - For a busy Time Machine only, which files your own processes writing a lot have open, to find build output it keeps copying; and whether a folder is left out of backups.
  - The summary of the last kernel panic (`/Library/Logs/DiagnosticReports/.contents.panic`), the names and dates of panic reports in that folder, and macOS's note of whether this startup followed a panic (`/var/db/com.apple.DumpPanic.panicLogPathBreadcrumb`). The panic text is shown only in the panel and never put in a report.
  - For Test my network, it reads the Wi-Fi signal, noise, speed, and channel (from CoreWLAN), whether AirDrop's radio link is on, the DNS, VPN, and proxy settings (from SystemConfiguration, as `scutil` does), and how much data each process moved in the last second (from Apple's `nettop`); none needs a permission. It never asks for Location Services, so it never sees the network's name.
  - Also for Test my network: which VPN in macOS's own list is connected and its app's name (from SystemConfiguration and Launch Services, as `scutil --nc list` does); who set the server that looks website names up (the network, this Mac, or the VPN); the router's address, and whether the Mac gave itself an address because the router didn't hand one out (from SystemConfiguration). To tell whether a VPN carries websites' traffic and name lookups, it asks the routing table which way traffic to a public address (Cloudflare's `1.1.1.1` and `2606:4700:4700::1111`) and to the name server would go, by setting up a UDP socket that sends nothing. None needs a permission, and none is stored or logged.
  - When the Cleaner's page opens (at most once a minute): the names and dates of what's in `~/Library/LaunchAgents` (and each plist's label and program path, to see whether the program still exists), `~/Library/Logs`, `~/Library/Saved Application State`, `~/Library/Caches`, `~/Library/PreferencePanes`, and `/Library/PreferencePanes`; the sizes of `~/Library/Developer/Xcode/DerivedData`, `~/Library/Caches/Homebrew`, `~/.npm/_cacache`, and `~/Library/Caches/Google/Chrome`; the bundle IDs of the apps in `/Applications` and `~/Applications` (and one folder down), whether Launch Services knows an app with a given ID, and which apps are open; for a settings pane, its bundle ID and the developer Team ID in its signature and in the installed apps' signatures; the names in the folders where developers put helpers and drivers (`LaunchAgents`, `LaunchDaemons`, `PrivilegedHelperTools`, `Extensions`, `Filesystems`, `Audio/Plug-Ins/HAL`, `Application Support`, in `/Library` and your own Library); "Install macOS" apps in `/Applications`; and whether the Mac is managed (`profiles status -type enrollment`). It never reads Containers, Group Containers, or the contents of any file, and none of this needs a permission. Downloads is read only when you choose a folder with Check Downloads… (choosing it is what lets Cool Head read it without macOS asking): file names, sizes, and dates, the disk images open now (`hdiutil info`), and, for a file named like a second download ("Report (1).pdf"), whether its bytes match the first. Nothing is kept or sent; the activity log records only counts.
  - For the This Mac page, when it opens: the Mac's model name (the IORegistry's device tree, as `ioreg` reads it), its serial number (`IOPlatformSerialNumber`, which any user can read), and the startup disk's size and free space. The serial number identifies the Mac, so it's shown on that page only, with a copy button: it never goes into a problem report, the shared database, or `coolhead` output, and the selftest only says whether it was read.
  - Reading a job's log in Documents, Desktop, Downloads, or iCloud Drive may make macOS ask whether Cool Head can access that folder; saying no only means those jobs get less detailed cards.
  - **The past week.** When you open the history, it reads macOS's own power log, `/private/var/db/powerlog/Library/BatteryLife/CurrentPowerlog.PLSQL` and the daily archives beside it, which every user on the Mac can read. It opens them read only and never writes to them.
  - From that log it reads three tables, by name, and no others: energy per app and program (`PLCoalitionAgent_EventInterval_CoalitionInterval`), sleep and wake events (`PLSleepWakeAgent_EventForward_PowerState`), and the reason for each wake (`PLSleepWakeAgent_EventForward_PowerState_Array_Reason`).
  - It never reads the rest of that database, which also records which app was in front and when, app launches, network use, and connected devices. SQLite itself refuses to let Cool Head read any other table, and on every build `coolhead selftest` checks that against a decoy app-usage table.
  - It decompresses each archive in memory, never to disk, keeps only the totals, in memory, and stores or sends nothing from it.
- **The chip's temperature.** macOS has no public way to read it either, so Cool Head asks macOS's sensor service the way monitoring tools do (`IOHIDEventSystemClient`, functions Apple doesn't document, looked up by name when first used) and keeps the hottest of the chip's own sensors (named `tdie`). It needs no permission and only reads. It reads it every 3 seconds while the panel is open, and with the other hardware checks every 10 minutes; nothing else is read from that service. If a future macOS changes it, only the chip's temperature stops showing, and it never decides a card: macOS's own thermal state does. `coolhead selftest` checks the reading is quick and sane.
- **Not Responding.** macOS has no public way to ask which apps are Not Responding, so Cool Head asks the window server the way Activity Monitor and Force Quit do (`SLSEventIsAppUnresponsive`, a private macOS function, looked up when it starts). It needs no permission and reads only that yes or no for each running app. If a future macOS removes it, only that kind of card stops; `coolhead selftest` checks it is there.
- **What it stores.** Nothing about what happened, with two exceptions. Spells of tight memory, kept 30 days in its preferences (key `pressureEpisodes`), each with when it began and ended, how tight it got, how much was moved to disk, whether the Mac was slowed, and the kind of program using the most (Chrome, another browser, an app, a job, macOS, or other; never a name), only so it can tell whether memory is what slows this Mac and how often; remove it with `defaults delete io.github.thephildiamond.coolhead pressureEpisodes`. And the names of macOS's own services that are busy, with when each started and was last busy, so a service still busy after a restart can be told apart; each is forgotten two days after it was last busy. Also, so it can put things back, the paths of what the Cleaner moved to the Trash and where each went, kept in its preferences until the item leaves the Trash (put back, or the Trash emptied), at most 200. Its settings (notifications, open at login, automatic update checks, tool names, the menu bar icon) and your own choices (apps and jobs you mark Always trust, reminders to resume a sync app you paused, and jobs paused until you plug in) are kept by macOS in its standard preferences and login items, on this Mac only. macOS keeps notification text in Notification Center, so notifications never name a process or project.
- **What it keeps in memory.** While running, a short anonymised record of its own activity (which cards appeared and cleared, which buttons were pressed and what happened) for Report a problem: at most 6 hours and 300 entries, never written to disk, gone when it quits.
- **What it sends.** A daily request to GitHub's public API for the latest release, to offer updates (off on the Settings page). Updates are installed only if their Ed25519 signature matches the key built into the app; see [docs/UPDATES.md](docs/UPDATES.md). Apart from that, nothing by itself.
  - Look it up opens a web search for a process name in your browser.
  - Start test, in Test my network, runs Apple's `/usr/bin/networkQuality` (by its full path, with fixed arguments, never through a shell), which downloads and uploads test data to and from Apple's servers for up to 30 seconds; it uses your whole connection and, on a fast line, a few gigabytes of data, and warns first on a phone or metered connection. It never runs by itself, and stops when you close the panel or quit Cool Head. Which option you then press is recorded in the activity log by a fixed id only, never by an app's name.
  - Start test also asks Cloudflare's public trace page (`https://www.cloudflare.com/cdn-cgi/trace`) where the request came from, through Apple's `/usr/bin/curl` (by its full path, with fixed arguments, HTTPS only, never through a shell). The page answers with the address it saw and that address's country; Cool Head shows only the country, and keeps the address in memory only to compare, never shown, stored, or logged. With a VPN that carries websites' traffic, it asks a second time over the Wi-Fi or cable directly, around the VPN, so Cloudflare sees your own address for that one request; that is how it tells whether the VPN hides it. It never runs by itself, only with the test. Cloudflare sees what any website sees: your address and that a request was made.
  - Share this case shows an anonymised report inside the panel; Open in GitHub sends that text to GitHub in the link and opens it in your browser, where it is posted, under your GitHub account, only if you press Submit.
  - Report a problem works the same way, adding the person's own words and that activity record.
  - Neither report holds paths, command lines, file or folder names, log lines, user or project names, or developer Team IDs; on every build, `coolhead selftest` builds a report from a made-up process full of private details and fails if any of them appears.
- **What it can change.** Only your own processes, and only when you press a button.
  - Stop asks first, names the process, and is never offered for macOS's own programs or an app's main program (those get Quit, which lets the app ask to save).
  - Run it cooler, Pause until you plug in, and Resume (for a process something else paused) don't ask, because each can be undone; Force quit, for an app macOS marks Not Responding, asks first, as Stop does; a paused job carries on when you plug in, when you press Resume now, when Cool Head quits, and when it next starts, so nothing is left frozen.
  - Security, device management, and VPN software is never offered Stop, Run it cooler, or Quit.
  - Cool Head changes one of Chrome's settings, only when you press **Set Memory Saver to Maximum**: while Chrome is closed for its restart, it changes two values in Chrome's `Local State` file (`performance_tuning.high_efficiency_mode` `state` and `aggressiveness`, to on at Maximum), only if no Chrome is using that folder, checking that nothing else in the file changed and keeping its permissions. It becomes your own setting: Chrome doesn't say it's managed, and you change it back in Chrome's Performance settings. Cool Head keeps the date it did this, so it doesn't ask again for 30 days if you lower it.
  - Cool Head no longer changes Chrome's policies. Versions 0.5 to 0.15 offered **Limit Chrome**, which wrote three of Chrome's documented settings to Chrome's preferences on this Mac (TotalMemoryLimitMb, and Memory Saver on, at Maximum), as `defaults write com.google.Chrome` would. Chrome only applies that memory limit when an organization manages the Mac, so it did nothing, while Chrome said it was "managed by your organization". Cool Head now removes those three settings when it starts, only where it wrote them; if you deleted Cool Head first, remove them with `defaults delete com.google.Chrome TotalMemoryLimitMb`, then the same for HighEfficiencyModeEnabled and MemorySaverModeSavings. For Chrome's other settings it copies the address for you to paste.
  - **Restart Chrome, keeping your tabs** (also Edge, Brave, Vivaldi, and Chromium) asks the browser to quit the normal way, so it can ask about downloads first, waits up to 20 seconds for it to close, and then opens it again with Chromium's `--restore-last-session` switch; if it hasn't closed by then, it isn't reopened. It reads nothing of the browser's own files.
  - **Unload a model** asks Ollama on this Mac to unload it now (`keep_alive: 0`, Ollama's own way); nothing is lost, and Ollama loads it again the next time it's asked something.
  - **The Cleaner** moves things to the Trash, only when you press a button, and each button asks first ("Move 3 items to the Trash?", then a second click). Nothing is deleted outright; Cool Head lists what it moved and can put each back. It never moves anything signed by Apple except an "Install macOS" app older than the running macOS, never anything in macOS's own folders, and never anything inside an app. Before moving, it checks each path is still inside the places it scans once every link is followed (a link itself moves as a link; its target stays). Quick clean: background helpers in your own `~/Library/LaunchAgents` whose program is gone (each stopped with `launchctl bootout` in your own login session first, which needs no password), log files and crash reports in `~/Library/Logs` not changed for 30 days, and macOS's saved windows (`~/Library/Saved Application State`) for apps that are gone. Deep clean, only what you tick: what's inside `~/Library/Developer/Xcode/DerivedData`, `~/Library/Caches/Homebrew`, `~/.npm/_cacache`, and `~/Library/Caches/Google/Chrome` (never while Xcode or Chrome is open; the folders themselves stay); settings panes in `~/Library/PreferencePanes` and `/Library/PreferencePanes`; folders in `~/Library/Caches` named for an app that's gone; "Install macOS" apps in `/Applications`; and installers and identical second downloads in a folder you choose.
  - **Items in a folder for all users** (`/Library/PreferencePanes`, an "Install macOS" app) need an administrator's password: macOS asks, then runs one command as a one-shot launchd job (`SMJobSubmit`), `/bin/mv -n` from each item to your own Trash, with each name passed as its own argument (never read by a shell), and the job is removed straight after, so nothing stays installed. Cool Head can't put these back itself; Show opens the Trash at the item, and Finder asks for the password to move it back.
  - **Delete Xcode's build data** asks first, then deletes what's inside `~/Library/Developer/Xcode/DerivedData` and nothing else; Xcode rebuilds what it needs.
  - **Stop** and **Force Quit** end a program at once, with no chance to save, so the first click only warns "Anything unsaved will be lost" and a second click within 5 seconds goes ahead.
  - **Stop it starting by itself**, offered only for another app's background helper (never macOS's own: a label starting `com.apple.` only when Apple didn't sign the program it starts; and never security software), asks first and is marked Caution: it runs `launchctl disable gui/<your user id>/<label>` and `launchctl bootout` for that helper, in your own login session, which needs no password. What the helper did for its app stops too. Turn it back on (its line at the top of the panel) runs `launchctl enable` and `launchctl bootstrap` from the same plist. If you delete Cool Head first, run `launchctl enable gui/$(id -u)/<label>` in Terminal yourself, with the helper's label in place of `<label>` (it's in the line's details, and looks like `com.google.keystone.agent`); `$(id -u)` fills in your user ID for you.
  - **Stop and delete it**, offered only for a program of yours pretending to be part of macOS (see Disguise.swift), asks first and is marked Caution: it stops the program (`SIGTERM`), moves it to the Trash, where you can put it back, and, for one started by an item in your LaunchAgents folder labelled like Apple's, turns that item off as above and moves it to the Trash too. It never moves anything in macOS's own folders or signed by Apple.
  - **Keep … out of Time Machine**, offered only for a folder named as build output (DerivedData, build, .build, .gradle, target, dist, node_modules, .next, __pycache__, Pods) inside your home folder, leaves it out of later backups, the way `tmutil addexclusion` does without `-p` (an attribute on the folder itself; no password). Back it up again (its line at the top of the panel) removes it; so does `tmutil removeexclusion` followed by the folder's path, in Terminal (for example `tmutil removeexclusion ~/Projects/app/build`).
  - Before acting, Cool Head checks the process is still the one the card was about.
