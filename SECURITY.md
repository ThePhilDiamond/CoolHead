# Security

Please don't report security problems in a public issue. Use GitHub's private reporting instead: on this repository, open the **Security** tab and choose **Report a vulnerability**. You'll get a reply there.

How Cool Head works, so you can judge what is a problem:

- **What it reads.** It runs as your user and reads what macOS lets your user read: details of your own processes (command line, folder, the files they write, the last lines of their logs) and, for other users' processes such as macOS's own, only their name and CPU use.
  - It also reads how much of the graphics chip each process uses, from the IORegistry (the same place `ioreg` reads), which needs no permission.
  - For the whole Mac, it reads macOS's memory pressure level, swap size and the running count of memory moved to the swap files (the counts `vm_stat` shows), and the free space on the startup disk; none needs permission.
  - Hardware checks, read the same way with no password: the internal drive's own health record (wear, spare space, errors), through Apple's public plug-in for it.
  - The battery's condition, charge cycles, temperature and charger, from the IORegistry, and its condition and Maximum Capacity from System Information (`system_profiler SPPowerDataType`), at most once an hour.
  - Error counters on each USB-C and MagSafe port, from the IORegistry.
  - The background helpers other apps install, from their plists in `~/Library/LaunchAgents` and `/Library/LaunchAgents` (read as files, again only when one of those folders changes), to tell whether a busy process is one; and, once you've turned one off, `launchctl print-disabled` for your login session, at most once a minute, to keep its line at the top of the panel current.
  - For a busy Time Machine only, which files your own processes writing a lot have open, to find build output it keeps copying; and whether a folder is left out of backups.
  - The summary of the last kernel panic (`/Library/Logs/DiagnosticReports/.contents.panic`), the names and dates of panic reports in that folder, and macOS's note of whether this startup followed a panic (`/var/db/com.apple.DumpPanic.panicLogPathBreadcrumb`). The panic text is shown only in the panel and never put in a report.
  - For Test my network, it reads the Wi-Fi signal, noise, speed and channel (from CoreWLAN), whether AirDrop's radio link is on, the DNS, VPN and proxy settings (from SystemConfiguration, as `scutil` does), and how much data each process moved in the last second (from Apple's `nettop`); none needs a permission. It never asks for Location Services, so it never sees the network's name.
  - Reading a job's log in Documents, Desktop, Downloads or iCloud Drive may make macOS ask whether Cool Head can access that folder; saying no only means those jobs get less detailed cards.
  - **The past week.** When you open the history, it reads macOS's own power log, `/private/var/db/powerlog/Library/BatteryLife/CurrentPowerlog.PLSQL` and the daily archives beside it, which every user on the Mac can read. It opens them read only and never writes to them.
  - From that log it reads three tables, by name, and no others: energy and wakeups per app and program (`PLCoalitionAgent_EventInterval_CoalitionInterval`), sleep and wake events (`PLSleepWakeAgent_EventForward_PowerState`), and the reason for each wake (`PLSleepWakeAgent_EventForward_PowerState_Array_Reason`).
  - It never reads the rest of that database, which also records which app was in front and when, app launches, network use, and connected devices. SQLite itself refuses to let Cool Head read any other table, and on every build `coolhead selftest` checks that against a decoy app-usage table.
  - It decompresses each archive in memory, never to disk, keeps only the totals, in memory, and stores or sends nothing from it.
- **Not Responding.** macOS has no public way to ask which apps are Not Responding, so Cool Head asks the window server the way Activity Monitor and Force Quit do (`SLSEventIsAppUnresponsive`, a private macOS function, looked up when it starts). It needs no permission and reads only that yes or no for each running app. If a future macOS removes it, only that kind of card stops; `coolhead selftest` checks it is there.
- **What it stores.** Nothing about what happened. Its settings (notifications, open at login, automatic update checks, Save Battery When Unplugged, tool names, the menu bar icon) and your own choices (apps and jobs you mark Always trust, reminders to resume a sync app you paused, and jobs paused until you plug in) are kept by macOS in its standard preferences and login items, on this Mac only. macOS keeps notification text in Notification Center, so notifications never name a process or project.
- **What it keeps in memory.** While running, a short anonymised record of its own activity (which cards appeared and cleared, which buttons were pressed and what happened) for Report a problem: at most 6 hours and 300 entries, never written to disk, gone when it quits.
- **What it sends.** A daily request to GitHub's public API for the latest release, to offer updates (off from the right-click menu). Updates are installed only if their Ed25519 signature matches the key built into the app; see [docs/UPDATES.md](docs/UPDATES.md). Apart from that, nothing by itself.
  - Look it up opens a web search for a process name in your browser.
  - Start test, in Test my network, runs Apple's `/usr/bin/networkQuality` (by its full path, with fixed arguments, never through a shell), which downloads and uploads test data to and from Apple's servers for up to 30 seconds; it uses your whole connection and, on a fast line, a few gigabytes of data, and warns first on a phone or metered connection. It never runs by itself, and stops when you close the panel or quit Cool Head. Which option you then press is recorded in the activity log by a fixed id only, never by an app's name.
  - Share this case shows an anonymised report inside the panel; Open in GitHub sends that text to GitHub in the link and opens it in your browser, where it is posted, under your GitHub account, only if you press Submit.
  - Report a problem works the same way, adding the person's own words and that activity record.
  - Neither report holds paths, command lines, file or folder names, log lines, user or project names, or developer Team IDs; on every build, `coolhead selftest` builds a report from a made-up process full of private details and fails if any of them appears.
- **What it can change.** Only your own processes, and only when you press a button.
  - Stop asks first, names the process, and is never offered for macOS's own programs or an app's main program (those get Quit, which lets the app ask to save).
  - Run it cooler, Pause until you plug in, and Resume (for a process something else paused) don't ask, because each can be undone; Force quit, for an app macOS marks Not Responding, asks first, as Stop does; a paused job carries on when you plug in, when you press Resume now, when Cool Head quits, and when it next starts, so nothing is left frozen.
  - Security, device management, and VPN software is never offered Stop, Run it cooler, or Quit.
  - Cool Head changes another app's settings in one case: **Limit Chrome**, when you press it, writes three of Chrome's documented settings to Chrome's preferences on this Mac (TotalMemoryLimitMb, and Memory Saver on, at Maximum), as `defaults write com.google.Chrome` would. Chrome then says it's "managed by your organization". It isn't offered if Chrome already has any of them, and Remove (its line at the top of the panel) removes only what Cool Head set. If you delete Cool Head first, remove them with `defaults delete com.google.Chrome TotalMemoryLimitMb`, then the same for HighEfficiencyModeEnabled and MemorySaverModeSavings. For Chrome's other settings it copies the address for you to paste.
  - **Restart Chrome, keeping your tabs** (also Edge, Brave, Vivaldi, and Chromium) asks the browser to quit the normal way, so it can ask about downloads first, waits up to 20 seconds for it to close, and then opens it again with Chromium's `--restore-last-session` switch; if it hasn't closed by then, it isn't reopened. It reads nothing of the browser's own files.
  - **Stop it starting by itself**, offered only for another app's background helper (never macOS's own, labels starting `com.apple.`, and never security software), asks first and is marked Caution: it runs `launchctl disable gui/<your user id>/<label>` and `launchctl bootout` for that helper, in your own login session, which needs no password. What the helper did for its app stops too. Turn it back on (its line at the top of the panel) runs `launchctl enable` and `launchctl bootstrap` from the same plist. If you delete Cool Head first, run `launchctl enable gui/$(id -u)/<label>` yourself; the label is in the line's details.
  - **Keep … out of Time Machine**, offered only for a folder named as build output (DerivedData, build, .build, .gradle, target, dist, node_modules, .next, __pycache__, Pods) inside your home folder, leaves it out of later backups, the way `tmutil addexclusion` does without `-p` (an attribute on the folder itself; no password). Back it up again (its line at the top of the panel) removes it; so does `tmutil removeexclusion <folder>`.
  - Before acting, Cool Head checks the process is still the one the card was about.
